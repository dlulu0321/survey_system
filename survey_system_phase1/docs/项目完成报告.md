# 基于 MongoDB 的问卷系统开发——第一阶段项目报告

## 一、项目目标

按照课程大作业初始需求，开发一个简化在线问卷系统。注册用户可以创建、管理和发布问卷；填写者通过公开链接进入问卷并提交答案；问卷创建者可以查看自动统计结果。系统重点体现MongoDB文档建模、后端业务逻辑、条件跳转、输入校验、测试与AI辅助开发记录。

## 二、系统设计

系统采用 Flask 作为 Web 后端，HTML/CSS/JavaScript 实现前端交互，MongoDB 作为业务数据存储。后端按职责拆分为：
- app.py：处理 HTTP 路由、登录会话和业务流程；
- db.py：处理 MongoDB 连接和索引；
- schema.py：定义和组织数据文档结构；
- logic.py：实现题目校验、条件跳转和统计逻辑；
- templates/、static/：保存页面模板、样式和前端脚本；
- tests/：保存自动化测试。

系统主要流程：注册/登录 → 创建问卷 → 编辑题目及跳转规则 → 发布并分享链接 → 填写并校验 → 保存一次提交记录 → 创建者查询统计。

## 三、MongoDB数据建模

数据库包含users、surveys、responses三个集合。

- users：保存唯一用户名、密码哈希和注册时间等信息；
- surveys：保存问卷所有者、公开ID、标题、说明、匿名设置、状态、截止时间、题目数组及时间戳；
- responses：独立保存问卷引用、填写者ID、答案对象和提交时间。匿名提交时，填写者ID可以为null。

问卷题目嵌入surveys.questions，因为问卷展示的时候需要一次性读取题目及其规则；回答记录独立存入responses，避免大量填写导致单个问卷文档不断膨胀。系统使用用户名和公开ID唯一索引，以及问卷所有者/创建时间、问卷/提交时间等查询索引。详见 `数据库设计.md`。

选择MongoDB的主要原因是不同题型具有不同的配置字段，文档结构可以表达选项、文本长度、数字范围和跳转规则等信息。但文档数据库并不意味着不需要结构约束，系统还是需要在后端验证数据类型、必填项和取值范围。

## 四、题目与跳转设计

第一阶段支持single、multiple、text、number四种题型。校验由后端执行：必答题必须提供有效答案；选项题答案必须属于有效选项；多选题要检查最少/最多选择数量；文本题检查长度限制；数字题检查数值格式、上下界和整数要求。

条件跳转规则保存在题目自身的jump_rules数组中，按配置顺序匹配第一条规则。设计支持eq、contains、gt、gte、lt、lte操作符，目标通过题目ID引用。没有规则命中时按题目顺序继续；目标为null的时候结束问卷。前端逐题交互，后端在提交时重新计算有效填写路径并校验答案。

## 五、问卷状态、填写和统计

问卷状态包含draft、published、closed。草稿不能公开填写；发布后在截止时间前可填写；关闭或超过截止时间后不能填写。未启用匿名时填写者必须登录；启用匿名时允许未登录提交，并将respondent_id设为null。每次提交独立保存，因此同一用户可以多次填写。

统计根据原始回答记录实时计算：单选统计每个选项被选择人数，多选统计每个选项被选择次数，文本填空展示回答内容，数字填空展示有效数字和平均值。统计页面和API检查问卷所有权，避免未授权用户查看结果。

## 六、测试方案与结果

项目包含tests/test_logic.py和tests/test_app.py。测试覆盖题目结构、条件跳转、必答校验、数字限制、多选限制、创建问卷、添加题目、发布、提交、统计、权限隔离及匿名填写。详见 `测试用例.md`。

在项目虚拟环境中执行以下步骤，把实际结果填入测试记录。

```powershell
python -m py_compile app.py
python -m unittest discover -s tests -v
```

## 七、遇到的问题与处理

1. **题目结构不同。** 如果每种题型都单独设计一套数据库集合，会增加读取和扩展复杂度。采用统一公共字段加题型专属字段的文档结构，并在后端集中校验。
2. **跳转后必答校验。** 被跳过的题目不要再被要求填写，后端要根据跳转规则计算实际填写路径。
3. **回答数量可能持续增长。** 每次提交独立保存到responses，统计时按问卷ID查询。
4. **问卷权限。** 服务端要核验问卷所有者和请求权限。
5. **代码修改可能引入回归问题。** 修复后要重新运行语法检查、自动化测试和核心流程手动验收。

## 八、第二阶段兼容性考虑

第一阶段仅实现初始需求，为了便于后续扩展：

- 文档保留schema_version，方便编写迁移脚本；
- 题目用typ区分题型，跳转条件以数据配置表示；
- responses独立存储，方便新增统计维度；
- 统计从原始提交记录计算，避免新增维度时多个预聚合计数不一致；
- 后续修改保留现在的接口和字段语义，并补充回归测试。
