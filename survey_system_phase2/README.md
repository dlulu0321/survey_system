# 基于 MongoDB 的问卷系统（第一、二阶段）

> 课程大作业实现：Flask + MongoDB。此版本在第一阶段基础上加入可复用题库、共享题目、不可变版本、使用情况追踪与跨问卷统计。

## 1. 功能清单

- 用户注册、登录、退出；密码使用 Werkzeug 的安全哈希，不保存明文密码。
- 用户只能查看、编辑和统计自己创建的问卷；填写者通过 `/survey/<public_id>` 访问。
- 创建问卷，填写标题、说明、匿名策略；题目 JSON 可编辑；发布、截止时间、关闭。
- 支持 `single`（单选）、`multiple`（多选）、`text`（文本填空）、`number`（数字填空）。
- 支持必答、多选最少/最多选择数、文本最短/最长长度、数字上下界、整数限制。
- `jump_rules` 存在问卷题目文档中，前端逐题导航并由后端重复验证跳转路径上的答案。
- 保存每次提交；支持匿名提交开关；统计单选/多选计数、文本回答、数字平均值。
- 提供 JSON API 与 `unittest` 测试。

## 2. 环境准备

需要 Python 3.10+ 和正在运行的 MongoDB。Windows 上请先启动 MongoDB 服务，再执行以下命令。

```powershell
cd survey_system_phase1
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

编辑 `.env`，将 `SECRET_KEY` 改为随机长字符串，并确认 `MONGODB_URI` 与 MongoDB 服务地址一致。默认连接 `mongodb://127.0.0.1:27017`，数据库名为 `survey_system`。

```powershell
python app.py
```

浏览器打开 `http://127.0.0.1:5000`。首次运行时应用会创建需要的索引。生产部署必须使用随机 `SECRET_KEY`、HTTPS，并将 `COOKIE_SECURE=true`。

## 3. 创建问卷的步骤

1. 注册账号并登录。
2. 点击“新建问卷”，填写标题和说明，选择是否允许匿名填写。
3. 创建后进入编辑页面，在题目 JSON 文本框中配置题目。一个有效题目示例：

```json
{
  "id": "q1",
  "title": "你更喜欢哪种水果？",
  "type": "single",
  "required": true,
  "options": ["苹果", "香蕉", "西瓜"],
  "jump_rules": [
    {"operator": "eq", "value": "苹果", "target_question_id": "q3"}
  ]
}
```

4. 保存题目并发布。系统会生成类似 `/survey/随机公开ID` 的填写链接。
5. 填写者提交后，问卷创建者可以在“统计”页面查看统计结果。

完整题型和跳转字段说明见 `docs/API与规则说明.md`。

## 4. 测试

```powershell
python -m unittest discover -s tests -v
```

测试使用 `mongomock` 模拟 MongoDB，测试数据不会写入真实数据库。测试用例及测试记录模板见 `docs/测试用例.md`。提交前应在自己的环境安装依赖并运行测试，将实际运行结果填入报告；不要把未运行的测试写成已通过。

## 6. 第一阶段范围与限制

- 当前题目编辑器使用 JSON 配置，优先保证题型和规则表达清楚；不是完整的拖拽式问卷设计器。
- 跳转规则按数组顺序匹配第一条满足的规则；没有规则匹配时按题目顺序继续，匹配到 `target_question_id: null` 时结束问卷路径。
- 匿名策略在本实现中表示：允许未登录用户提交，且其 `respondent_id` 保存为 `null`。未勾选匿名时，填写者必须登录。
- 同一用户可以重复填写；初始需求没有要求防止重复提交，因此不额外限制。
- 统计由已保存的回答记录实时计算，不维护易产生不一致的预聚合统计值。
- 这是课程原型。生产环境还应加入 CSRF 防护、登录限流、审计日志、邮件找回密码等安全与运维能力。


## 7. 第二阶段：题库与题目版本

第二阶段新增功能入口为登录后的“题库管理”页面：

- **保存常用题目：** 在题库管理页输入单道题目的 JSON，保存为题目系列 v1；系统会自动加入“我的题库”。支持单选、多选、文本、数字四类题型。
- **创建题库：** 可以新建命名题库，并把可访问的题目版本加入相应题库。
- **从题库选择：** 在草稿问卷编辑页点击“从题库选择题目”，再对指定版本点击“加入问卷”。每次选择都会把题目复制为问卷内的独立快照。
- **题目共享：** 打开题目详情，在“分享题目”中填写已注册用户的用户名。被分享用户可以查看和使用该题目版本，不能修改原作者的版本历史。
- **版本历史：** 题目详情页可查看每个版本、父版本和修改说明；创建新版本不会覆盖旧版本。
- **恢复旧版本：** 恢复操作会复制指定旧版本的内容，创建新的版本号，不删除或覆盖已有历史。
- **使用情况：** 题目详情页列出所有引用该题目系列的问卷及所用版本。
- **跨问卷统计：** 将使用相同题目系列的问卷回答合并统计，并提供按版本分项的数字汇总、选项计数或文本回答样例。
- **发布后冻结：** 已发布问卷的题目不允许直接修改。需要修改时，使用“复制为草稿”创建独立草稿，然后再编辑或换用其他题目版本。

题库题目的 JSON 例子：

```json
{
  "title": "你的年龄？",
  "type": "number",
  "required": true,
  "min_value": 0,
  "max_value": 120,
  "integer_only": true
}
```

题库模板不保存 `jump_rules`，因为跳转目标是特定问卷中的其他题目。把模板加入问卷后，再在问卷 JSON 中设置跳转规则。题目版本不变；若问卷内的快照被人工修改，系统会解除其题库来源标记，避免把已改变语义的问题错误地合并进该题的跨问卷统计。

## 8. 从第一阶段升级

1. 先备份整个项目目录和 MongoDB 数据库；不要删除或覆盖现有 `.env`。
2. 将本压缩包中的程序文件合并到现有项目，保留你的 `.env`、虚拟环境和数据库目录。
3. 在现有 `.venv` 中执行 `python -m pip install -r requirements.txt`（依赖未变化时可略过）。
4. 启动 MongoDB，再执行 `python app.py`。首次请求时会自动创建第二阶段需要的索引和新集合。
5. 运行自动化测试，并在浏览器验证新题库功能。

旧问卷会保留原有题目和回答。旧问卷中的题目因为没有题库来源标记，不会自动纳入跨问卷题库统计；若希望未来纳入统计，请把需要复用的题目保存为题库题目，并在新问卷中选择对应版本。不要对已有数据库做清空操作。

## 9. 第二阶段测试

```powershell
python -m py_compile app.py logic.py schema.py db.py
python -m unittest discover -s tests -v
```

新增测试位于 `tests/test_phase2.py`，覆盖题目复用、版本快照、发布题目冻结、共享题目及跨问卷统计。只有在本机实际执行后，才可把测试报告标记为通过。详细操作见 `docs/第二阶段测试用例.md`，数据字段与升级细节见 `docs/第二阶段升级说明.md`。
