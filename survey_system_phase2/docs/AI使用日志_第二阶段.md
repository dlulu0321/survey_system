# AI 使用日志（第二阶段需求变更）

## 1. AI 帮了什么

- 读取并梳理了需求变更中的八类反馈：常用题保存复用、共享、发布后保护、历史版本、多个版本并存、查看使用关系、题库管理、跨问卷统计。
- 检查第一阶段Flask + MongoDB项目结构，沿用已有 `users`、`surveys`、`responses` 和原有题型校验逻辑，设计新增的题目系列、题目版本、题库和题库条目集合。
- 起草版本化题库、共享权限、把具体版本复制为问卷快照、发布后题目冻结、复制为草稿、使用情况追踪和跨问卷统计代码与模板。
- 编写第二阶段测试用例、升级说明等。

## 2. AI 输出可能的错误或不足

- 生成代码可能存在运行时问题，即使Python语法检查通过，也不代表Flask路由、MongoDB查询和Jinja模板均已在目标环境运行。
- 题库题目与问卷内题目的ID、跳转规则和版本来源是不同层次的数据；若不保留快照或来源校验，可能把修改后的题目误认为原版本并污染跨问卷统计。
- 跨问卷统计涉及不同版本；如果题目含义变化，简单合并所有版本的结果造成误解，因此实现了总体数字摘要和按版本拆分的展示。

## 3. 我需要人工核对和修改的内容

- 在本机安装/激活项目依赖，运行 `python -m py_compile app.py logic.py schema.py db.py` 与 `python -m unittest discover -s tests -v`。
- 按 `docs/第二阶段测试用例.md` 手动验证创建题目、创建版本、恢复版本、分享、选入问卷、发布后冻结、复制草稿、使用关系和跨问卷统计。
- 确认实际 MongoDB 连接地址及数据库名，不覆盖 `.env`，测试前备份现有数据。
- 如果本机实际运行中出现错误，需要以报错为准修复代码，并将真实结果补记到本日志。

## 4. 自己设计或作出的判断

- 保留第一阶段问卷中嵌入题目快照的模型，避免题库改动直接改变已有问卷。
- 将题目系列与具体版本分开，使用父版本字段记录历史关系。
- 将发布后的题目冻结；如需修改，复制为新的草稿。
- 题目加入问卷时保留来源系列和来源版本标识，以支持使用关系和跨问卷统计。
- 对题目跳转规则不直接作为题库模板复用，因为跳转目标依赖具体问卷里的其他题目。
