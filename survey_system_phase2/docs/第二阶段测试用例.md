# 第二阶段测试用例

> 使用已有项目时先备份 `.env` 和 MongoDB 数据。测试问卷应使用独立的测试账号和测试数据。

## 一、自动化测试

在激活项目 `.venv` 后执行：

```powershell
python -m py_compile app.py logic.py schema.py db.py
python -m unittest discover -s tests -v
```

语法检查不报错，测试命令结束时显示 `OK`。

## 二、创建题库题目

1. 启动 MongoDB 和 Flask，打开 `http://127.0.0.1:5000`。
2. 注册并登录测试用户。
3. 点击顶部“题库管理”。
4. 在“新建并保存常用题目”区域输入一题，例如：

```json
{
  "title": "你的年龄？",
  "type": "number",
  "required": true,
  "min_value": 0,
  "max_value": 120,
  "integer_only": true
}
```
5. 点击保存。预期进入题目详情页，版本历史出现 v1；回到题库管理，默认题库显示该题。

## 三、创建不同版本并查看历史

1. 在题目详情页的“创建新版本”区域，将标题改成“你的年龄（岁）？”，将max_value改为 150，修改说明写“调整题目描述和范围”。
2. 提交新版本。预期出现v2，v1也可以查看，v2的父版本指向v1。
3. 点击v1的“恢复此版本为新版本”。预期产生v3，而v1、v2仍然存在，v3内容与v1相同。
4. 检查每个版本的创建时间、版本号、修改说明和父版本记录。

## 四、从题库向问卷添加题目

1. 新建问卷，保存为草稿。
2. 在问卷编辑页面点击“从题库选择题目”。
3. 选择一个具体版本，点击“加入问卷”。
4. 检查题目JSON：题目具有新生成的问卷内ID，并包含来源系列ID、来源版本ID和版本号。
5. 选择其他版本加入另一份草稿，两份问卷可以分别保存不同版本。

## 五、发布后冻结题目

1. 将使用v1的问卷A发布，并至少提交一份回答。
2. 回到问卷管理，尝试编辑A中的题目JSON并提交。服务器拒绝更改，并提示已发布问卷题目被冻结。
3. 尝试通过API更新发布问卷题目（自动化测试覆盖这一点）。
4. 点击“复制为草稿并修改题目”。生成新的草稿ID和公开ID；修改新草稿的题目不影响A的题目和原回答。

## 六、分享题目

1. 使用账号A创建题目。
2. 确认账号B已注册。
3. 在题目详情页把题目分享给B的用户名。
4. 退出A，使用B登录并打开题库管理，可以看到被共享题目。
5. 使用B创建草稿问卷，将共享题目加入问卷。
6. 用B尝试打开A的问卷管理地址或修改A的版本历史，但是没有权限。

## 七、查看使用关系与跨问卷统计

1. 创建两份草稿问卷，分别加入同一题目系列的v1和v2。
2. 发布两份问卷并分别提交数字答案，20和30。
3. 在题目系列详情页检查“哪些问卷使用了这个题目”，会列出两份问卷和对应版本。
4. 检查跨问卷统计：有效回答数2，数字样本数2，平均值25，范围20～30；按版本统计分别显示v1和v2的结果。
5. 对单选/多选版本可检查选项计数；对文本版本可检查部分文本答案。

## 八、数据和兼容性检查

MongoDB Shell 中执行 `show collections`，可以看到原有 `users`、`surveys`、`responses`，以及新增的 `question_families`、`question_versions`、`question_banks`、`question_bank_items`。

确认已有第一阶段问卷和回答仍可查看。已有问卷没有题库来源字段，因此不会自动进入第二阶段跨问卷统计；这是为了避免在无法确认原题语义与版本关系时错误归并数据。
