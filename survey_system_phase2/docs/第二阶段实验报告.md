# 第二阶段需求变更实现报告

## 1. 需求背景

第一阶段使用Flask和MongoDB实现用户、问卷、题目、跳转、提交和问卷内统计。需求变更提出用户希望将常用题目保存复用、共享给其他用户、为题目保留多个版本、查看使用关系，并跨问卷统计同一题目的回答。第二阶段在原项目上增量开发，不替换原有问卷与回答集合。

## 2. 功能实现

| 需求变更 | 实现方式 | 验证入口 |
|---|---|---|
| 保存常用题目 | question_families保存题目系列，question_versions保存不可变定义；创建后加入“我的题库” | 登录 → 题库管理 → 新建并保存常用题目 |
| 新建/管理题库 | question_banks保存用户题库，question_bank_items关联题库和具体版本 | 题库管理页创建题库并添加版本 |
| 从题库选题 | 把具体版本定义复制进草稿问卷，生成问卷内题目ID | 草稿问卷 → 从题库选择题目 → 加入问卷 |
| 分享给其他用户 | 题目系列保存share_with_ids；接收者可以查看和使用，但不能修改原作者的版本历史 | 题目详情 → 分享题目；用接收者账号登录验证 |
| 发布后冻结题目 | 表单与API都拒绝修改已发布问卷的问题配置；可复制为草稿后编辑 | 发布问卷后尝试修改题目，再复制草稿验证 |
| 版本历史与血缘 | 每个版本记录version、parent_version_id、change_note；旧版本不更新覆盖 | 题目详情 → 版本历史 |
| 恢复旧版本 | 复制指定历史定义，生成新的递增版本号，父版本指向当前版本 | 题目详情 → 恢复此版本为新版本 |
| 查看被哪些问卷使用 | 扫描问卷快照中的题目来源系列/版本字段，展示引用问卷和版本 | 题目详情 → 哪些问卷使用了这个题目 |
| 跨问卷统计 | 基于同一题目系列的问卷快照和对应回答集合汇总有效回答；同时保留版本分项结果 | 题目详情 → 跨问卷统计 |

## 3. 数据模型变更

新增四个集合：

- question_families：题目系列、所有者、共享用户、根版本和更新时间。
- question_versions：不可变的题目定义、版本号、父版本、创建者、修改说明和时间。
- question_banks：用户管理的题库名称和说明。
- question_bank_items：将具体题目版本加入一个题库的关系记录。

原有surveys.questions继续嵌入题目，防止问卷显示和旧数据依赖一个随时变化的“最新题目”。从题库加入问卷时，系统复制题目内容，并记录source_question_family_id、source_question_version_id、source_question_version。所以A问卷可以保存v1，B问卷选择v2；后续创建v3不会修改A或B中已经保存的快照。

新增索引覆盖题目系列所有者/更新时间、共享用户、系列与版本号、父版本、题库名和题库内的题目版本唯一关系。

## 4. 重要提示

1. 题库模板不携带jump_rules，跳转目标取决于所在问卷中的其他题目，加入问卷后再设置。
2. 已发布的问卷中的题目配置会被冻结，需要修改时复制为草稿，但是原问卷和已收集的回答保持不变。
3. 恢复历史版本是“创建新版本”，不是删除当前版本或覆盖旧版本。
4. 共享用户只能使用分享给自己的题目，不能修改分享者的版本历史；为了避免泄露其他人的问卷数据，共享接收者只能查看自己问卷的使用情况与统计，题目所有者可查看该题系列的跨问卷汇总。
5. 如果用户直接编辑草稿中的题目，让定义与来源版本不同，系统会去掉题库来源标记，防止跨问卷统计把不同语义的题目错误合并。
6. 以前的问卷没有题目库来源标记，因此不会自动进入新题库的跨问卷统计，旧数据不会被删除或者强行迁移。
7. 跨问卷统计包含同一题目系列的多个版本，并同时显示按版本拆分的统计。如果修改了题目含义，分析时应优先比较版本分项，而不应盲目混合解释。
