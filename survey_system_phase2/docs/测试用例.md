# 测试用例与执行记录（第一阶段）

## 1. 自动测试

测试文件：`tests/test_logic.py`、`tests/test_app.py`。测试使用 `mongomock` 提供隔离的 MongoDB 行为模拟，不会污染正式数据库。执行命令：

```bash
python -m unittest discover -s tests -v
```

| 编号 | 覆盖点 | 输入/步骤 | 预期结果 |
|---|---|---|---|
| UT-01 | 题目 schema | 使用包含单选、数字、文本题的题目数组调用 `validate_questions` | 合法题目返回；重复 ID、无效题型或不存在的跳转目标报错 |
| UT-02 | 单选跳转 | q1 选 A，规则目标为 q3 | `next_question_id` 返回 q3；选 B 且无匹配规则时按顺序继续 |
| UT-03 | 必答校验 | 提交缺少必答 q1 的答案 | 抛出 `ValidationError`，错误信息指出必答题 |
| UT-04 | 数字校验 | 整数题提交 20.5，或超出 0～120 | 校验失败；提交 20 通过 |
| UT-05 | 多选限制 | 多选题要求至少 2 项、最多 2 项；分别提交 1 项、重复项、2 个合法选项 | 前两种失败，合法的两项通过 |
| IT-01 | 创建问卷 | 登录后 `POST /api/surveys`，提交标题 | 返回 HTTP 201，包含问卷 ID 和公开 ID |
| IT-02 | 添加题目 | 对新问卷 `PUT /api/surveys/<id>/questions` | 返回 HTTP 200，题目数量与输入一致 |
| IT-03 | 发布问卷 | 添加至少一道合法题目后调用发布接口 | 状态变为 `published`，返回公开链接 |
| IT-04 | 登录限制 | 未登录用户提交不允许匿名的问卷 | 返回 HTTP 401 |
| IT-05 | 提交问卷 | 登录填写者提交有效答案 | 返回 HTTP 201，`responses` 新增一条记录 |
| IT-06 | 选项校验 | 单选题选项为 A/B，却提交 C | 返回 HTTP 400，提示无效选项 |
| IT-07 | 统计 | 提交后查询问卷统计 API | 总提交数和选项计数正确；数字平均值按有效数字计算 |
| IT-08 | 权限隔离 | 非创建者查询他人问卷统计 | 返回 HTTP 404，不泄露资源是否存在的权限细节 |
| IT-09 | 匿名提交 | 问卷允许匿名，未登录提交文本答案 | 返回 HTTP 201，回答记录 `respondent_id` 为 `null` |

## 2. 手工测试步骤

1. 启动 MongoDB，安装依赖并启动 Flask 服务。
2. 浏览器打开首页，注册用户 A；验证重复用户名注册失败。
3. 用户 A 登录并创建问卷，配置单选、多选、文本、数字四种题型。
4. 保存题目，设置一条单选跳转规则，例如选“苹果”跳至 q3，发布问卷。
5. 在无痕窗口打开公开链接。未启用匿名时应要求登录；启用匿名后可直接填写。
6. 测试必答为空、多选少于最小数量、文本过长、数字超范围、整数题输入小数等情况，确认后端拒绝非法答案。
7. 提交一份合法问卷，确认出现提交成功提示。
8. 回到用户 A 的问卷列表打开统计页，核对总提交数、各选项次数、文本答案和数字平均值。
9. 注册用户 B，确认 B 的问卷列表看不到 A 的问卷，B 访问 A 的统计 API 得到 404。
10. 用户 A 关闭问卷，再访问公开链接，页面应提示不可填写；设置截止时间并验证截止后的问卷同样不可提交。
